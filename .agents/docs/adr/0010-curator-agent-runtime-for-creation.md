# Curator Agent Runtime For Thinkspace Creation

Better Agent will implement the **Curator** as a concrete durable conversational runtime for Thinkspace creation: a per-draft `CuratorAgent` Durable Object built on Project Think (`@cloudflare/think`, ADR-0006), distinct from the **Thinkspace Agent** runtime and keyed on the draft Thinkspace id — one Curator per draft, not one per user. Creation becomes a live conversation: the user describes intent, and the Curator shapes the draft and its first **Agent Profile** revision through a deliberately propose-only toolset — set the **Goal**, configuration summary, instructions, and model, and enable tools (which auto-derive the matching requested **Permissions**, mirroring `updateToolSelections`). The Curator is handed no activate and no grant tool; "proposes, never grants" is therefore a structural property of its toolset rather than a runtime check it could forget, and activation stays a user-only action. The static creation form is removed: the Curator is the only path to create a Thinkspace, and the DRAFT Thinkspace row is minted the moment a curation conversation starts (consistent with the schema's existing intent that a Thinkspace "begins as a draft the moment the user starts shaping it with the Curator").

We are choosing a durable per-draft conversational agent over the lighter alternatives because goal-curation — sharpening a vague intent into a bounded, assessable **Goal** — is the crux of the product, and incremental refinement ("narrow the goal", "drop that tool") is only natural when each turn mutates a live draft the user watches converge on an **agent card**. That card is the Think substrate's synced agent state (`setState` → `onStateUpdate`), with D1 as the authoritative source of truth and the card a live projection refreshed after each tool's write, so activation and every other read stay consistent with the rest of the system. The Curator resolves the user's product-level model credential **ungated by any Thinkspace Permission**: the granted-credential Permission is specifically the boundary for a **Thinkspace Agent**'s access to the user's key (a different role), whereas the Curator is the user employing their own key to set up their own Thinkspace — it crosses no Thinkspace boundary and runs before any Thinkspace Agent exists. It runs on the user's default model unless a per-user "Curator model" setting overrides it; with no credential at all the product gates creation and directs the user to connect one.

Considered alternatives: a stateless propose-draft endpoint (rejected — it is one-shot wearing a conversation costume and wastes the durable substrate the refinement loop needs); a single per-user Curator Durable Object hosting every creation plus routing and the Review Queue (deferred — it interleaves unrelated draft histories and over-builds the per-user role before the creation slice is proven, while per-draft keying leaves routing and the cross-Thinkspace Review Queue as a clean future slice); keeping the static form as a fallback (rejected — two creation paths fragment the experience; the form survives only conceptually as the no-credential floor that points users to connect a provider); and enforcing propose-never-grant with a runtime guard (rejected in favor of simply not handing the Curator the tools). Scope is creation only; the `CuratorAgent` is keyed on the Thinkspace id (which survives activation) so a later reconfiguration slice re-enters the same runtime to shape a superseding revision, and the curation conversation persists in the Durable Object's durable history. The standing constraint, reinforcing ADR-0006 and ADR-0009, is that Project Think's session, state-sync, and tool mechanics are implementation tools: the **Curator**, the **Agent Profile** draft it proposes, and the **Permission** and **Approval** the user grants remain the authoritative product concepts — and a connected-account tool the Curator proposes still answers to its three distinct gates: the **Connected Account** must exist (product-level), the **Permission** must be granted (per Thinkspace, at activation), and each action still needs an **Approval** (at runtime).
