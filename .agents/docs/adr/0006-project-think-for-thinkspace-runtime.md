# Project Think For Thinkspace Agent Runtime

Better Agent will use Cloudflare Project Think (`@cloudflare/think`) as the first implementation layer for the durable **Thinkspace Agent** runtime, rather than building directly on raw Cloudflare `Agent` or `AIChatAgent`. Project Think is the runtime substrate for the agent loop, durable message/session storage, recovery, streaming, programmatic submissions, and tool execution mechanics. Better Agent's product model remains authoritative: **Thinkspace**, **Goal**, **Permission**, **Approval**, **Review Queue**, **Memory**, **Source**, **Artifact**, **Audit Trail**, **Attention**, and **Backpressure** are not replaced by Think's implementation terms.

We are choosing Project Think because Better Agent's primary runtime identity is one durable Thinkspace Agent per Thinkspace, and Think already provides the closest Cloudflare-native shape for long-lived agent work: Durable Object-backed state, Session-backed messages, recovery, server-side `submitMessages()` entry points, and lifecycle hooks for constraining tools and observing runtime actions. Raw `Agent` would require rebuilding too much of that substrate. `AIChatAgent` is too chat-surface-oriented for the first Better Agent runtime slice, where durable authenticated submission and later inspection are more important than immediately exposing a generic chat UI.

The first implementation should live in the API/runtime Worker and use an app-owned authenticated submit/inspect path before exposing any browser-reachable Think route. Direct `/agents/*` routing must not be public unless Better Auth session checks and Thinkspace ownership checks run before the request reaches the agent router. The stable runtime instance name is the Thinkspace id, not the user id, conversation id, session id, or Goal text.

Think's built-in workspace, memory, session, MCP, and approval concepts are implementation tools only. A Think Session is an interaction surface inside one Thinkspace; Think workspace files are runtime-local state unless promoted through Better Agent's Source/Artifact rules; Think context and compaction are not accepted Memory; Think tool approval is a pause/transport primitive, not the product-level Approval model. Better Agent's Permission and Approval policy remains the authority for tool availability and external mutations.

The first runtime slice must restrict Think aggressively: disable workspace Bash, keep `maxSteps` low, and return no active tools or only explicitly safe read-only tools until Thinkspace-scoped Permissions and Review Queue-backed Approvals are implemented. MCP servers must not be registered merely because a Connected Account or product-level catalog entry exists; only Thinkspace-enabled tools governed by Permission policy may be connected later.

Considered alternatives: building directly on raw Cloudflare `Agent`; using `AIChatAgent` as the initial runtime; adopting Think's Vite framework conventions immediately; keeping a request-scoped API-only model. The consequence is deliberate coupling to Project Think's experimental but purpose-built runtime APIs in exchange for much less custom durable-agent infrastructure. The offsetting constraint is that Better Agent must maintain a clear domain boundary around Project Think so runtime conveniences do not silently become user-facing product semantics.
